Codex-Arbeitsmodus

Jeder Implementierungsprompt referenziert genau ein Modul. Codex muss vor dem Coding die Modul-Spec lesen und im Abschlussbericht nachweisen, welche Anforderungen umgesetzt wurden.

Prompt-ElementPflichtinhalt
ZielEin klarer Satz: welcher sichtbare App-Bereich wird verbessert?
Blueprint-Quellez. B. specs/orders.md und orders.html.
UmfangWelche Route/Helper/Tests gehören zum Modul?
AkzeptanzWelche UI ist sichtbar besser? Welche Daten/Status stimmen?
TestsDB-Test, UI/static check, Browser-Retestpfad.
Final MappingBlueprint requirement | Implemented file | Status | Notes.

Beispiel für Orders-Prompt

Roadmap step: Orders Work Queue alignment
Blueprint source: docs/operations-kit-blueprint-v0.4-app-sorted/specs/orders.md and orders.html
Goal: Orders list and Order Detail must match Orders UI wireframes.
Expected visible result: filters, products/quantities, address readiness, derived status, next action, order-line decision detail.
Final report must map each Orders Blueprint requirement to implemented files.
