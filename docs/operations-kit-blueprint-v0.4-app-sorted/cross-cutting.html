Querschnittsregeln

RegelBeschreibung
Tabellenfilter wie ExcelJede große Work Queue hat Filter für Text, Status, Datum, Zahl, Boolean und Relation. Clear filters ist Pflicht.
Next ActionJede Work Queue und Detailseite zeigt eine fachlich eindeutige nächste Aktion mit Grund.
Page OwnershipListen priorisieren Arbeit; Detailseiten führen die jeweilige Prozessaktion aus. Fremde Prozessaktionen werden nicht auf falschen Seiten versteckt.
Blocked StateBlocker müssen sichtbar sein: fehlender Lieferant, fehlende Adresse, fehlender Bestand, fehlende BOM, ungültige Kundendaten.
Event/Audit späterDetailseiten erhalten Events-Tabs; zunächst darf dies leer/placeholder sein, aber Mutationen sollen perspektivisch Events schreiben.
Keine Testhilfe als FachlösungDev Backfill darf Demo-Daten retten, aber echte Akzeptanz läuft über Shopify Sync und echte Prozessdaten.

Statusmodelle zusammengefasst

BereichStatus
OrdersNeeds planning → Purchase proposal ready → Purchase Order created → Sent to supplier → Awaiting receipt → Receiving/QC → Putaway pending → Ready for logistics → Shipment created → Complete; Blocker: Logistics blocked, Review required.
Purchase NeedNeed supplier → Ready for PO → Converted to PO → Cancelled. MVP-Aliase müssen klar gemappt werden.
Purchase OrderDraft → Approved optional → Sent → Supplier acknowledged optional → Receiving allowed → Closed/Complete.
ReceiptExpected → Received/QC required → QC completed → Putaway pending → Closed.
ShipmentReady → Created → Packed optional → Shipped → Complete; kein Shopify Fulfillment Writeback im MVP.
