Test-Szenarien

Jeder Codex-Lauf muss auf mindestens ein Szenario einzahlen.

Scenario A: Handelsware Quantity 1

  1. Shopify Order für sichtbares Produkt, Menge 1.
  2. Operations Kit: Sync Orders.
  3. Orders zeigt 1 × SKU Title, Status Needs planning oder Purchase proposal ready.
  4. Procurement erzeugt Need automatisch/idempotent.
  5. Purchase Need Menge = 1.
  6. PO erstellen, PO Line Menge = 1.
  7. Approve/Send/Acknowledge.
  8. Goods Receipt erstellen.
  9. QC accepted=1 rejected=0.
  10. Putaway to inventory.
  11. Inventory zeigt Bewegung und Bestand.
  12. Logistics erzeugt Shipment wenn Adresse vorhanden.

Scenario B: Handelsware Quantity 3

Wie A, aber Menge 3. Erwartung: Purchase Need = 3, PO Line = 3, Receipt accepted = 3, Putaway = 3.

Scenario C: QC Rejected

  1. Goods Receipt Menge 3.
  2. QC accepted=2 rejected=1.
  3. Accepted geht in Putaway, rejected in Quarantine.
  4. Order bleibt teilweise offen/blockiert, bis Ersatz oder manuelle Entscheidung.

Scenario D: Logistics blocked wegen Adresse

  1. Order vollständig eingelagert.
  2. Adresse fehlt.
  3. Orders Status: Logistics blocked.
  4. Logistics zeigt konkrete Gründe: Name/E-Mail/Shipping address fehlt.
  5. Dev Backfill Test Address.
  6. Status: Ready for logistics.
  7. Create shipment.

Scenario E: Kit Product später

  1. Kit hat BOM mit 2 Komponenten.
  2. Order Quantity 2 Kits.
  3. Komponentenbedarf = BOM × 2.
  4. Fehlende Komponenten erzeugen Purchase Needs.
  5. Build Kit konsumiert Komponenten und erzeugt Kit-Bestand.
