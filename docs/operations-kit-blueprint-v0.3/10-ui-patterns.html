UI Patterns

These patterns are implementation rules. If a future page cannot follow one of them, the implementation prompt must state why and update the Blueprint first.

Work Queue Page Pattern

AreaRequired behavior
ToolbarExplicit labels only: Sync Shopify orders, Refresh planning, Refresh purchasing needs, Export, Saved views later. No one-letter buttons.
PurposePrioritize work and show next action. A work queue may open a detail page, but should not execute actions that belong to another process detail.
FiltersEvery major table column must be filterable with the standard filter types below.
TableReference, status, core entity, quantity/value, blocker reason, next action, open detail.
RowsCompact rows; row click opens detail. Inline forms are allowed only if they remain compact and are owned by that page.
Next actionExactly one primary next action per row or section. Secondary links are allowed only when they open related records.
Saved viewsLater feature. Reserve UI language: Open, Blocked, Due, Mine, Completed, Products on shop, Needs supplier.

Detail Page Pattern

AreaRequired behavior
Toolbar topBack link plus either Save/Cancel for master data or lifecycle actions for process details. Button labels must include the object/action subject.
SummaryReference, status, counterparty/customer/supplier, important quantities, blocker reason, next action.
TabsUse Header, Lines, Related work, Receipts, Inventory outcome, Address, Events as applicable.
FormsForms are compact and scoped. Master Data pages use one page-level Save where practical. Process forms save exactly one process step.
Next Action PanelOne primary action + reason + target. Never show generic "Open" without object name.
EventsEvery mutation should create an audit/event record once the event model exists.

Master Data Form Pattern

RuleImplementation detail
Owns attributesProduct owns item type, sellable, purchasable, producible, supplier policy, QC policy, BOM summary. Supplier owns supplier header and supplier-item terms. Customer is read-only in MVP.
Does not execute operationsNo MRP run, no PO creation, no receipt, no QC, no putaway, no shipment creation on master data pages.
LayoutCompact grids, tables and summary rows. Avoid tall single-column forms for small numeric fields.
Blocked statesShow master data blockers where they are caused: missing supplier on Product, missing BOM on Product/BOM, missing address on Customer/Order.

Process Detail Pattern

Process detailOwned actionsForbidden actions
Purchase Order DetailApprove, Send to supplier, Mark supplier acknowledged, Create Goods Receipt, Cancel PO.Complete QC, Put away, Create shipment.
Receipt DetailComplete QC, Put away to inventory.Create PO, Send to supplier, Create shipment.
Shipment DetailMark packed, Mark shipped, Cancel shipment.Procurement, receiving, inventory correction, Shopify fulfillment writeback in MVP.

Excel-like Table Filter Pattern

Filter typeUse forExample
Text containsSKU, title, order number, PO number, customer email, supplier name.SKU contains WAX.
Status dropdownOperational status, PO status, receipt status, QC status, shipment status.Ready for PO, Awaiting receipt.
Date rangeOrder date, expected date, received date, shipped date, updated date.Expected delivery before today.
Number min/maxQuantity, available stock, line value, lead time, MOQ.Quantity greater than 0.
Boolean yes/noAddress present, supplier assigned, BOM active, QC required, on shop.Address present = no.
Relation dropdownSupplier, customer, product, item type, location.Supplier = Test Trading Supplier.
Missing-data filterSupplier missing, address missing, BOM missing, Shopify status missing, price missing.Show products missing BOM.

Applies to Products, Suppliers, Customers, Orders, Procurement, Receiving, Inventory, Logistics and BOM / Kitting. Every work queue must include Clear filters. Saved views are later unless already implemented.

Toolbar Pattern

ContextAllowed labelsForbidden labels
Master data detailBack to Products, Save, Cancel, Back to Suppliers, Deactivate supplier.S, C, Back, Open without object.
OrdersSync Shopify orders, Refresh planning, Open order, Open in Shopify.R, O, generic Sync.
ProcurementRefresh purchasing needs, Create Purchase Order, Approve, Send to supplier, Mark supplier acknowledged.Acknowledge without subject, Create without object.
ReceivingCreate Goods Receipt, Complete QC, Put away to inventory, Back to Receiving, Back to Procurement.Post receipt somewhere, Put away without inventory context.
LogisticsCreate shipment, Open shipment, Backfill test address (development only).Ship without local-only/Shopify-writeback distinction.

Blocked, Empty, Status and Event Patterns

PatternRequired behavior
Blocked StateUse a warning/critical badge, exact reason, owner page and next action. Example: Missing supplier → Open Product Detail.
Empty StateTell the user what data is missing and which existing action creates it. Example: Sync Shopify orders to create operational demand.
Status BadgeUse domain status labels from 04 Status Models. Do not collapse all work to "in progress" when precise status exists.
Audit/Event timelineShow event type, actor, timestamp, linked object and short message. Event timeline is read-only on detail pages.
Data quality blockerNever hide a blocker in a paragraph. It must be visible in summary, table row and detail section where relevant.
